## Blockers

None confirmed. Two intermittent playback defects (M1, M2) were seen only in the headless software-GL session; they should be re-checked once on a real GPU desktop before tagging, because both sit in the player path, which the engine now draws.

## Majors

**M1. Dark grid lines across the playing video, intermittent, Glass, Spotlight and Marquee.** In the first themed run, the player capture (pointer moved so the controls show, about 1 s later) of Glass, Spotlight and Marquee had a lattice of thin dark horizontal and vertical lines over the whole video (Glass: dozens of lines, Spotlight and Marquee: fewer). NOCTURNE, Feed and Classic were clean. Re-runs did not reproduce it: Glass three captures in a row (`/tmp/qa52/themes/glass-player-a.png`, `-b`, `-c`) and Spotlight twice (`spot-r2.png`) were clean, and two successive Glass frames differ across the whole image only because the video moved. The lines are not in the theme CSS (no `repeating-` gradient in the starters). Evidence of the defect: `/tmp/qa52/themes/glass-player.png`, `spotlight-player.png`, `marquee-player.png`, overview `/tmp/qa52/themes/players.png`. Suspect: the transparent hole or its sub-rectangles over the Wayland subsurface during the controls' first draw, or the software compositor path. Unconfirmed on a GPU.

**M2. Player stays on "Opening" forever and the app then ignores SIGTERM.** Three times the player never left "Opening" (no error, no timeout): the Spotlight movie re-run (`/tmp/qa52/t/hung.png`, 6 minutes later still "Opening" with an interactive UI), and the episode "Seedlings" reached by the random-key run (`/tmp/qa52/perf/mid.png`). In both cases the process was in `futex_wait` with `SigCgt` including TERM, `timeout` sent TERM and the process stayed alive for 14 minutes until SIGKILL (pids I started myself). The audio backends fail in this session (jack and PipeWire connect errors in the log, `couldn't open play stream`), so an mpv open that waits on audio is the likely trigger, but the app should still show an error after a bounded time and exit on TERM. Worth one run on a real desktop with and without an audio server.

**M3. Resident memory with a 5,012-item library is high and keeps creeping while a video sits on "Opening".** `fast-release`, A server plus the 5,000-file local source, 10 minutes of scripted browsing (library, shows, search, detail, back, End/Home): 647 MiB at 30 s, 868 at 60 s, 924 at 300 s (plateau 920 to 950 while browsing), then 957, 968, 977, 980 MiB over the last four samples while the app sat in the stuck player. For comparison the idle Home figure in `docs/dev/PERF.md` is 325 MiB with the engine. The local items have no artwork, so it is not the image cache. Samples: `/tmp/qa52/perf/rss.csv`. CPU over the run averaged about 1.6 cores under the scripted key stream and software rendering (not an idle figure). Needs a decision: acceptable for a 5,000-item library, or find what the 600 MiB is (card data, scene nodes, the local index).

Without the marker the same rules are really ignored (`p1.png`). The report should say which engine read the CSS.

## Details by item

**1. Default look parity.** Engine build against a real `cargo build --no-default-features` binary, same demo data and sources: see minor 1 and 2. Search overlay differences are the hero slide behind the overlay only.

**2. Every theme, every screen.** NOCTURNE, Glass, Spotlight, Marquee, Feed and Classic on Home, Library, Movie detail, Series detail, Episode detail (opened from search), Search overlay and the player overlay (`/tmp/qa52/themes/sheet-*.png`, single captures `<theme>-<screen>.png`). Nothing essential hidden, no overlap, text readable. Notes: Feed has no hero by design (rows only), Marquee shows landscape cards without titles in the poster view by design, Classic carries the web-style header with icons and row arrows, Glass shows its pill header and rails. Player controls are present in all six (M1 and M2 aside). A one-row Episode page wraps "More ..." under the first button row at 1600 px in every theme (also in NOCTURNE); it is not hidden.

**3. Paste-a-theme.** Paste works (Ctrl+V needs `wtype -s 150 -k v` in this session; plain typed text is fine). A paste starts a preview on the whole app ("Previewing a theme", Keep, Revert), the preview survives navigation to Home (`p2.png`), Revert restores the built-in look (`p3.png`), Keep ends the bar with the look kept (`m3.png`). `@import url("https://jellyfin.catppuccin.com/theme.css");` fetched one file and reported "Fetched 1 file, 0 from the cache; 0 fonts loaded" plus the grouped counts (`i1.png`); the https address field downloads the same sheet (`u1-c.png`) and rejects a non-https address with "The address must start with https://". Ctrl+Shift+0 shows the toast "Safe look: the built-in theme" and a "Leave safe look" button (`u3.png`). `remote_css` off: minor 4. "Refresh imports": pressed, but the result line was scrolled out of the report box, so the cache hit was not verified (NOT TESTED).

**4. Server UI.** Both throwaway servers served `/web` so Jellyfin layout mode was in play for A (own UI) and for B's UI over "All sources" (B's branding CSS: dark red header, pink section titles; `/tmp/qa52/x/sheet.png`, bottom row against the top row). The merged catalog shows each demo title twice because both demo servers hold the same library without provider ids. Through logging pass-through proxies in front of both servers (method and path only, no tokens), the app made 437 requests, all GET (191 to A, 246 to B), with the default settings (server changes off): nothing was written to either server.

**5. Theme Studio.** Controls, driven through the panel's own messages with the debug `studio-script` hook (a pointer-only build would need hundreds of clicks): floating rounded header (radius, side margins, background), pill buttons for all `.button` ("All like this"), section accent bar (width, gap, colour), undo and redo, the CSS tab in step with the controls, Save writing the marked CSS into `themes.toml` (`/tmp/qa52/x/st1.png`, `st2.png`). Not done from scratch: the full-bleed backdrop hero and the logo title (they are data and layout of the detail page; the Glass starter provides them), Export (opens a portal file dialog that the headless session cannot answer), per-server use. Re-import was exercised by pasting a saved sheet into the Themes editor (item 3 path). Per-server assignment: NOT TESTED beyond the store's unit tests.

**6. Keyboard.** Home (Down, Right), card Enter to a library or detail, Esc back, `/` opens search, typed text, Down moves the result highlight, Esc closes, Tab moves between library tabs, Right and Down in the library grid, Enter opens the item (`/tmp/qa52/k/sheet.png`). A focus ring was visible after every key. No focus is shown on first load before any key. Gamepad (`NOCTURNE_PAD`) and Couch mode: NOT TESTED.

**7. Performance.** `NOCTURNE_ENGINE_STATS=1` ("engine: update N us", handling a message and rebuilding the scenes it changed) over 60 Down keys and wheel notches on the 5,012-item library: 940 and 547 samples, p50 0.2 to 0.4 ms, p95 3 to 4 ms, p99 7 to 9 ms, max 14 to 18.5 ms (9 of 940 over 8 ms, one over 16 ms).
